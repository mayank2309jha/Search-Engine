# query-server

The Python query-processing, ranking, and REST API layer of this search engine monorepo — the third component alongside [`crawler/`](../crawler/) (Python, fetches and stores pages + link graph) and the top-level C++ engine (`src/`, `include/`, builds `data/index.bin`).

This component owns: query understanding (tokenization, spell correction), query parsing (boolean AND/OR/NOT, phrases), multi-term BM25 + PageRank fusion ranking, semantic (embedding-based) re-ranking, snippets, deduplication, pagination, and the FastAPI REST layer. The C++ engine only ever answers single-word queries (`InvertedIndex::searchBM25()` takes one word) — this service is what makes multi-term, boolean, and semantic search possible at all.

## Running it

```bash
# from the repo root
cd query-server
python -m venv .venv && .venv/bin/pip install -r requirements.txt
PYTHONPATH=. .venv/bin/python -m uvicorn app.main:app --reload
```

Startup requires `../data/index.bin` to exist (built by the C++ engine — see the repo root `Readme.md`). It's a **hard dependency, not a fallback**: a missing index fails startup loudly rather than silently serving stale data. `../data/crawler.db` is optional — if present, results get real titles/snippets from crawled page text; if absent (common — it's gitignored crawl output that lives on whoever ran the crawl's machine), results still work correctly but with URL-derived titles and empty snippets.

Interactive API docs (Swagger UI, autogenerated by FastAPI): `http://127.0.0.1:8000/docs`

Offline evaluation and training scripts (run against the separate synthetic `data/corpus.json`, not live data — see `docs-ml/current-state.md`, local-only, not in this repo, for why):

```bash
PYTHONPATH=. .venv/bin/python scripts/evaluate.py           # Precision@10/MRR/nDCG@10, BM25 vs BM25+semantic
PYTHONPATH=. .venv/bin/python scripts/train_ranker.py        # fits BM25/PageRank fusion weights
PYTHONPATH=. .venv/bin/python scripts/tune_semantic_weight.py  # grid-searches the semantic blend weight
```
